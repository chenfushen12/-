# 库存跟踪系统规格

## Problem Statement

库存跟踪目前依赖多份本地 Excel：商品主模板、销售数据、北京库存和星望库存。人工合并这些文件容易产生重复统计、日期错位、库存未匹配和历史数据覆盖等问题，也无法稳定地展示销量趋势、MOH 和库存预警。

系统需要让单个用户在本地导入每日数据，按照 `GROUPCODE + 货品编号` 追踪商品，保留可审计的原始导入记录和每日库存快照，并通过清晰的 Tkinter 界面显示趋势、数据质量问题和库存风险。

## Solution

构建一个本地单用户 Tkinter 应用，以 SQLite 保存商品模板版本、销售明细、仓库库存快照、当前有效计算结果、导入日志和配置；以原始文件副本保存输入证据；以 pandas/openpyxl 负责 Excel 清洗和导出，以 matplotlib 在 Tkinter 中展示趋势图。

应用使用“预检查—预览—用户确认—一次提交”的导入流程。主模板、销售数据、北京库存和星望库存都通过严格的字段校验和数据质量分级后才能成为当前有效数据。库存快照按业务日期保存，销售数据按自然日追加或按重叠日期替换；同一文件哈希不得重复导入。

系统只为选定的库存快照日生成结果，不使用当前库存回算历史日期。历史结果依赖对应日期的北京和星望库存快照；缺少一个仓库时保存为 `partial`，显示已有数据但 MOH 和库存预警标记为“待补全”。

## User Stories

1. 作为库存运营人员，我想导入商品主模板，以便定义需要跟踪的商品范围。
2. 作为库存运营人员，我想在导入主模板前看到原始行数、有效商品数、重复行数和数据质量问题，以便确认导入内容。
3. 作为库存运营人员，我想让完全重复的商品主模板行自动去重，以便同一商品不会被重复计算。
4. 作为库存运营人员，我想在商品主键字段冲突时阻止提交，以便不会把不同商品错误合并。
5. 作为库存运营人员，我想让模板版本只有在预览确认后才生效，以便可以安全更换追踪商品范围。
6. 作为库存运营人员，我想导入包含多个自然日的销售文件，以便持续积累历史销量。
7. 作为库存运营人员，我想把销售数量按业务日期、GROUP CODE 和货品编号汇总，以便得到每天每个商品的净销量。
8. 作为库存运营人员，我想保留负销量退货并看到异常标记，以便识别退货影响而不是丢失信息。
9. 作为库存运营人员，我想阻止同一个销售文件重复导入，以便销量不会被重复累加。
10. 作为库存运营人员，我想在销售日期重叠时选择按日期替换，并保留原始文件和导入日志，以便修正数据而不丢失审计线索。
11. 作为库存运营人员，我想导入北京库存并只汇总指定库房代码，以便可用库存符合业务口径。
12. 作为库存运营人员，我想在设置页调整北京库房代码，以便适应仓库编码变化。
13. 作为库存运营人员，我想导入星望可用库存、采购在途和 30/90 天销量，以便计算整体库存风险。
14. 作为库存运营人员，我想让库存来源中的重复商品键按数值列求和，以便批次或库房拆分不会丢失库存。
15. 作为库存运营人员，我想看到北京或星望中未匹配的商品，而不是把空值静默转成 0，以便发现主数据问题。
16. 作为库存运营人员，我想把已成功导入日期中没有销售行的商品记为 0，以便区分真实无销量和缺少销售数据。
17. 作为库存运营人员，我想只使用不晚于库存快照日的销售数据，以便未来销售记录不会污染当前库存分析。
18. 作为库存运营人员，我想让 30 天和 90 天历史窗口独立判断完整性，以便一个窗口完整时仍可使用销售表计算值。
19. 作为库存运营人员，我想在历史不足时回退到星望文件中的对应销量并显示“历史不足”，以便结果仍可用且来源透明。
20. 作为库存运营人员，我想查看当前快照日的每日销量和环比，以便快速识别销量增长。
21. 作为库存运营人员，我想在前一日或当前日销量不满足增长计算条件时看到 `—` 和原因，以便不被误导性的百分比误导。
22. 作为库存运营人员，我想配置环比阈值，以便根据业务需要调整“快速增长”的定义。
23. 作为库存运营人员，我想看到北京可用库存、星望可用库存和在途库存，以便理解 MOH 的构成。
24. 作为库存运营人员，我想分别配置 30 天 MOH 和 90 天 MOH 阈值，以便处理两个销量窗口的不同尺度。
25. 作为库存运营人员，我想让 MOH 等于阈值时也触发低库存风险，以便边界商品不会被漏掉。
26. 作为库存运营人员，我想区分无库存、增长型缺货风险、常规低库存、滞销和数据质量异常，以便确定处理优先级。
27. 作为库存运营人员，我想允许一个商品同时显示多个预警标签，以便完整表达复合风险。
28. 作为库存运营人员，我想在只导入一个仓库时看到已有数据但看到“待补全”，以便不会误以为库存快照完整。
29. 作为库存运营人员，我想按日期回看历史结果，但历史结果应使用当时的商品信息和库房设置，以便审计结果不会漂移。
30. 作为库存运营人员，我想按商品、分类、日期、预警标签和数据质量筛选结果，以便快速定位需要处理的商品。
31. 作为库存运营人员，我想按预警严重度、低 MOH 和高环比排序，以便风险商品优先显示。
32. 作为库存运营人员，我想查看单个商品的销量、库存、在途和两个 MOH 的历史趋势，以便判断风险是短期波动还是持续变化。
33. 作为库存运营人员，我想修改阈值后按当前设置重新评估页面，同时保留快照原始阈值，以便兼顾日常调参和审计。
34. 作为库存运营人员，我想导出追踪结果、预警清单、数据质量报告和导入日志，以便进行汇报和进一步处理。
35. 作为库存运营人员，我想打开导入日志中的原始文件副本，以便追溯任何异常结果的输入来源。
36. 作为维护人员，我想通过自动化测试验证当前模板商品数动态计算、重复导入、日期替换、历史不足、缺仓库和预警边界，以便后续模板更新不会导致规则回归。
37. 作为维护人员，我想通过双击启动脚本或命令行启动应用，以便开发和日常使用都方便。

## Implementation Decisions

- 采用本地单用户 Tkinter/ttk 应用，不引入 Web 服务、云数据库或多人协作权限。
- 使用 SQLite 保存模板版本、销售数据、库存快照、当前有效追踪结果、配置和导入日志。
- 原始 Excel 由应用复制保存，并与数据类型、业务日期、文件哈希和导入记录关联；原始文件和导入日志永不删除。
- 计算结果不是历史版本库；同一快照日重新导入或补齐库存时，当前结果被覆盖，旧的计算结果不保留。
- 商品主键统一为字符串形式的 `GROUPCODE + 货品编号`；去除首尾空格，保留前导零，不自动进行大小写折叠。
- 主模板只读取有效主键行；空白样式占位行不计入商品数。
- 主模板完全忽略外链公式和公式重算，只使用当前工作簿中的静态缓存值。
- 主模板重复行自动去重；完全相同的重复项产生警告；同键字段冲突属于阻断问题。
- 当前修正模板的验收基线是动态有效商品数 26，但程序不得硬编码商品数。
- 主模板导入采用模板版本机制；预览确认后才启用新版本；历史快照保留当时商品字段。
- 销售时间转换为 Asia/Shanghai 自然日，不保留时间部分；未来日期排除计算并写入数据质量报告。
- 销售数量按业务日期、GROUP CODE 和货品编号聚合求和；负数量保留并标记异常。
- 缺少必要销售列、日期无法解析或数量无法解析属于阻断问题；缺少商品键的销售行排除并写入质量报告。
- 销售文件哈希重复时阻止导入；追加只允许不重叠业务日期；有重叠日期时强制按日期替换。
- 日期替换只替换对应日期的当前有效销售数据，并保留所有原始文件和导入日志。
- 库存业务日期默认是昨天，用户可以修改；库存日期是计算快照的基准日期。
- 北京库存默认精确匹配六个库房代码 `CB、CE、CS、CT、CL、FS`，设置页允许修改；不使用模糊库房名称匹配。
- 北京可用库存按选定库房和商品主键汇总 `可用数`。
- 星望库存按商品主键汇总参与计算的可用库存、采购在途、近 90 天销量和近 30 天销量。
- 库存未匹配显示空值并标记“未匹配”；不得把库存空值转成 0。
- 销售日期已导入但商品无销售行时记为 0，并标记“已确认无销量”；未导入日期不计为 0。
- 30 天窗口包含快照日及此前 29 天；90 天窗口包含快照日及此前 89 天。
- 30 天和 90 天历史完整性独立判断；完整窗口使用销售表窗口总销量，不完整窗口回退星望对应值并标记“历史不足”。
- 日环比只在当前日和前一日销量都大于 0 时计算；其他情况显示 `—` 并不触发增长预警。
- 环比阈值使用 `>=`；30 天和 90 天 MOH 阈值分别配置，默认均为 `2.5`，低库存使用 `<=`。
- MOH 使用库存总量除以对应窗口销量；销量为 0 时显示 `∞`，库存大于 0 时触发滞销品预警，库存总量小于等于 0 时触发无库存预警。
- 负库存保留原值并标记数据质量异常；不得静默截断为 0。
- 预警标签可叠加，严重度顺序为无库存、增长型缺货风险、常规低库存、滞销品、数据质量异常。
- 只生成选定库存快照日的追踪结果；历史日期必须有对应日期的北京和星望库存快照。
- 单仓库缺失时仍保存 `partial` 快照，展示已有数据，MOH 和库存预警显示“待补全”，不沿用旧快照、不把缺失仓库当作 0。
- 两个仓库齐全后重新计算同一天的当前结果；原始部分导入记录保留。
- 快照记录当时使用的模板版本、库存快照版本、库房代码列表、阈值和计算日期。
- 页面支持按当前配置重新评估预警，但不覆盖快照保存的原始阈值和原始商品信息。
- Tkinter 页面采用多标签页；导入中心内部采用预检查、预览和确认步骤。
- 仪表盘支持日期、商品、分类、预警标签和数据质量筛选；默认按预警严重度、低 MOH、高环比排序。
- 选中一个商品后展示销量、库存、在途和两个 MOH 的历史趋势。
- 导出使用静态值，不依赖 Excel 公式重算；至少包含追踪结果、预警清单、数据质量报告和导入日志。
- 数据质量分为阻断、警告和提示；只有阻断问题禁止提交，警告和提示需要用户确认后才能提交。
- 提供命令行入口和 Windows 双击启动脚本。

## Testing Decisions

- 测试外部行为和用户可观察结果，不测试 pandas 调用方式、SQLite 内部实现或具体 Tkinter 控件层级。
- 商品主模板测试应根据非空复合主键动态计算有效商品数，验证当前样例为 26，但不把 26 写死为业务规则。
- 主模板测试覆盖空白样式行过滤、完全重复自动去重、冲突重复阻断、外链公式忽略和模板版本确认。
- 销售导入测试覆盖日期标准化、未来日期排除、负销量保留、缺主键行排除、无效日期/数量阻断、文件哈希去重和重叠日期替换。
- 销售聚合测试验证同一日期和商品键的数量求和，以及“已导入日期无销售行=0”和“未导入日期=历史缺失”的区别。
- 窗口计算测试分别覆盖完整 30 天、完整 90 天、一个窗口完整而另一个不足、两个窗口都不足和窗口边界包含快照日。
- 库存测试覆盖六个库房代码精确匹配、库房代码设置变更、北京和星望重复键数值求和、库存未匹配、负库存和单仓库 `partial` 状态。
- 计算测试覆盖环比正增长、前一日为 0、当前日为负数、MOH 阈值等于边界、销量为 0、库存总量为 0 和库存总量为负数。
- 预警测试验证多标签叠加、严重度排序、滞销品预警、无库存预警、增长型缺货风险和常规低库存。
- 版本测试验证历史快照使用当时模板信息和库房代码，当前模板及设置变更不改变历史快照。
- 导入事务测试验证阻断问题不会写入半成品当前数据，确认后才提交，重复导入不重复累计。
- 导出测试验证四个工作表存在、输出为静态值、包含计算日期/版本/阈值元数据，并可由导入日志定位原始文件。
- UI 验收测试验证多标签页、导入预览确认、日期切换、筛选排序、单商品图表和“按当前设置重新评估”。
- 使用当前四类 Excel 和合成边界数据共同作为测试夹具，避免仅依赖当前样例的偶然行数和商品集合。

## Out of Scope

- 不做多人协作、账号权限、云同步或远程数据库。
- 不自动从电商或仓库系统下载数据。
- 不对外部 Excel 公式进行重算或修复外部工作簿链接。
- 不根据模糊相似列名猜测业务字段。
- 不使用当前库存回算没有对应库存快照的历史日期。
- 不在销售文件没有订单唯一编号的情况下进行不可靠的行级去重。
- 不保留同一天被替换前的旧计算结果；只保留原始输入文件和导入日志。
- 不在第一版实现多商品叠加趋势图、复杂权限模型或跨设备部署。
- 不把 MOH 重新解释为月数；计算遵循已确认的“库存除以近 30/90 天销量”口径。

## Further Notes

- 当前最新主模板只有 26 个有效商品，Excel 内部的高行号是样式占位，不是商品数据。
- 当前目录不是 Git clone，也没有可推断的 remote；GitHub 账号已认证，但账户下未发现名为“库存监控”的仓库。
